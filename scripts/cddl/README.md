# qlog CDDL validator

`scripts/validate-qlog.mjs` checks that qlog files strictly conform to the
CDDL of the latest published qlog drafts. qvis-react supports only these drafts:

| Draft | CDDL extracted to |
| --- | --- |
| draft-ietf-quic-qlog-main-schema-14 | `main-schema-14.cddl` (25 blocks) |
| draft-ietf-quic-qlog-quic-events-13 | `quic-events-13.cddl` (79 blocks) |
| draft-ietf-quic-qlog-h3-events-13 | `h3-events-13.cddl` (32 blocks) |

The validator reads both serializations:

- **JSON-SEQ** (`.sqlog`, `application/qlog+json-seq`, `QlogFileSeq`).
- **Contained JSON** (`.qlog`, `application/qlog+json`, `QlogFile`).

It uses the Rust [`cddl`](https://crates.io/crates/cddl) crate's CLI, tested
with version 0.10.7. Beyond that binary it has no dependencies: it is plain
Node ESM, needs Node 22 or newer for `JSON.parse` source access, and was tested
on Node 26.

## Files

| File | What it is |
| --- | --- |
| `../validate-qlog.mjs` | The validator. |
| `main-schema-14.cddl`, `quic-events-13.cddl`, `h3-events-13.cddl` | CDDL extracted verbatim from the published drafts (generated). |
| `qlog-latest.cddl` | The three combined, verbatim with identical duplicates kept once; compiles (generated by `validate-qlog.mjs --emit-spec-cddl`). |
| `event-types.json` | Map from event name to CDDL type, derived from the drafts (generated). |
| `extract-cddl.mjs` | Generates the three draft `.cddl` files and `event-types.json` from the published draft `.xml` + `.txt`. |
| `sample-valid.sqlog` | A small, strictly conforming JSON-SEQ qlog. |

## Setup

```sh
cargo install cddl --version 0.10.7 --root ~/.local/cddl   # any --root works
export CDDL_BIN=~/.local/cddl/bin/cddl                    # or put it on PATH
node scripts/validate-qlog.mjs --self-test                # 45 checks, prints "self-test passed"
```

## Usage

```sh
node scripts/validate-qlog.mjs path/to/file.sqlog other.qlog ...
node scripts/validate-qlog.mjs --json file.sqlog > report.json   # machine-readable report
node scripts/validate-qlog.mjs -q tests/fixtures/quic-go/*.sqlog  # one summary line per file
```

Exit codes:

| Code | Meaning |
| --- | --- |
| 0 | Every file passes. |
| 1 | At least one file has an error, or a warning when `-W` is set. |
| 2 | Usage or setup problem, such as the `cddl` CLI not being found. |

Options (`--help` lists them all):

| Option | Effect |
| --- | --- |
| `--cddl-bin <path>` | The cddl CLI to use. The default is `$CDDL_BIN`, then `cddl` on PATH. |
| `--batch <n>`, `--jobs <n>` | Items per cddl invocation (default 250) and parallel invocations (default: CPU count). |
| `--max-report <n>`, `--max-messages <n>` | How many failing events to print per file (default 25) and messages per event (default 8). 0 means all. |
| `--summary <n>` | Size of the per-file issue summary (default 40, 0 turns it off). |
| `--detail <n>` | Precise re-validation of array and union failures for only the first n failing events (default: all, 0 turns it off). |
| `--allow-unknown-events` | Events not defined by the three drafts become warnings instead of errors. |
| `-W` | Warnings also fail the file. |
| `--emit-cddl <f>` / `--emit-spec-cddl <f>` | Write the adapted or the verbatim combined CDDL. |
| `--check-cddl` | Compile both combined CDDLs with the CLI. |

### Report format

For each file the report has three parts:

1. **File-level problems**: header CDDL errors and semantic checks.
2. **Failing events**: the event index (0-based, counting events only, so the
   header record is not counted), the name, the concrete type its data was
   validated against, and each error as a JSON-pointer path relative to the
   event. When a message comes from the detail pass, the CDDL rule it was
   checked against is shown in brackets.
3. **Issue summary**: distinct problems with counts, grouped by event type,
   path pattern (array indices become `*`) and message. This part is the most
   useful when patching a producer.

For example, on a quic-go v0.64.1 fixture:

```
FAIL  tests/fixtures/quic-go/h3-5x200k-loss2-server.sqlog
      JSON-SEQ (QlogFileSeq): 2683 events, 2683 failing events, 4 file-level errors, 0 warnings (327 ms)
      ERROR event_schemas: "urn:ietf:params:qlog:events:quic-12" does not identify the supported draft; expected "urn:ietf:params:qlog:events:quic-13"
      ERROR header: unexpected key "qlog_version"
      ...
      event #7 "transport:packet_received" -> QUICPacketReceived (as quic:packet_received):
          /name: "transport:packet_received" uses namespace "transport", which is not defined in the supported drafts (did you mean "quic:packet_received"? data checked as QUICPacketReceived)
          /data: unexpected key "datagram_payload_checksum"
          /data/frames/0 [CryptoFrame]: object missing key: raw
          /data/frames/0 [CryptoFrame]: unexpected key "length"
      issue summary (45 distinct; count × event type  path [rule]: message):
             814 × quic:packet_sent  /data/frames/* [StreamFrame]: unexpected key "length"
             808 × quic:packet_sent  /data/header/version: expected <value> to match regex "^(?:([0-9a-f]{2})*)$"
             806 × quic:packet_sent  /data/header/key_phase_bit: expected type bool, got <value>
           ...
```

When an event uses a legacy name such as `transport:packet_sent` or
`recovery:metrics_updated`, the name is an error. Its `data` is still validated
against the probable current type (`quic:packet_sent` -> `QUICPacketSent`), so
one run lists everything that needs fixing.

## What is validated

1. **Header.** For a `.sqlog`, the first JSON-SEQ record is checked against
   `QlogFileSeq`. For a `.qlog`, the whole file is checked against `QlogFile`
   with each trace's `events` emptied, and the events are checked
   individually.
2. **Every event.** Each event is checked against `Event`, with
   `data: $ProtocolEventData` narrowed to the concrete type for its `name`.
   For example, the envelope for `quic:packet_sent` is
   `qvis-event-QUICPacketSent`, which is the spec's `Event` rule with
   `"data": QUICPacketSent`. Every value this envelope accepts is also a
   valid `Event`. The name-to-type map is `event-types.json`, which is derived
   from the drafts (57 event types: `loglevel:*`, `simulation:*`, `quic:*`,
   `http3:*` and `http:*`).
3. **Semantic checks** that CDDL cannot express:
   - `file_schema` and `serialization_format` must match the file kind (main-schema-14 Sections 4, 5, 11).
   - Each `name` must be `<namespace>:<event type>` (Section 8).
   - Event types not defined by the three drafts are errors by default; `--allow-unknown-events` makes them warnings.
   - `event_schemas` entries for quic, http3 and http must carry the draft suffix (`urn:ietf:params:qlog:events:quic-13`, `...:http3-13`, `...:http-13`); this is a MUST in "Draft Event Schema Identification". Main-schema-14 has no such rule for `loglevel` or `simulation`.
   - A warning is raised when events of a namespace are logged but its schema is not listed (a SHOULD in Section 8).
   - JSON-SEQ framing per RFC 7464: each record starts with 0x1E and ends with LF. A missing final LF is a warning (truncated file); elsewhere it is an error.
   - The file must be valid UTF-8.

## How the CDDL was obtained

The `.cddl` files are generated, so do not edit them. They are produced from
the published drafts by `extract-cddl.mjs`:

```sh
mkdir -p /tmp/qlog-ref && cd /tmp/qlog-ref
for d in main-schema-14 quic-events-13 h3-events-13; do
  for ext in xml txt; do curl -sSO https://www.ietf.org/archive/id/draft-ietf-quic-qlog-$d.$ext; done
done
node scripts/cddl/extract-cddl.mjs /tmp/qlog-ref        # writes the 3 .cddl files + event-types.json
node scripts/validate-qlog.mjs --emit-spec-cddl scripts/cddl/qlog-latest.cddl
```

The extraction works as follows:

- **Which blocks.** Every `<sourcecode type="cddl">` block of the published
  xml2rfc source is extracted, including two blocks outside figures:
  `SystemInformation`, and `$ApplicationError /= HTTP3ApplicationError`.
  Each block is cross-checked against the published `.txt` with whitespace
  normalized and page headers and footers removed. All 136 blocks match, so
  the CDDL is the published text.
- **Excluded figures.** `<artwork>` figures are examples and are excluded. Three
  of them are illustrations of the form `$QuicFrame /= { * text => any }`
  (also `$HTTP3Frame` and `$HTTPCapsule`). Including them would make any map a
  valid frame and switch off frame validation. The WG's `cddl_validate.sh`
  excludes them too, because it only extracts `~~~ cddl` blocks.
- **Combining.** `qlog-latest.cddl` combines the three files verbatim. The one
  duplicate rule, `Initiator`, is defined identically in quic-events-13 and
  h3-events-13 and is kept once. A conflicting duplicate would be an error.
  The combined file compiles with `cddl compile-cddl`; run
  `node scripts/validate-qlog.mjs --check-cddl` to confirm.
- **Event-name map.** Each event type is the heading of the section that holds
  its definition, and the type must be a member of the namespace's
  `<X>EventData` union. The map is cross-checked against each draft's
  "Name value" overview table.

## Adaptations for cddl-rs and JSON

The Rust crate does not implement some parts of RFC 8610, or implements them
differently. The validator therefore rewrites the combined CDDL in memory into
equivalent CDDL that the crate handles correctly. The rewrite touches code only,
never comments or string literals. Use `--emit-cddl` to inspect the result;
`--self-test` shows that each rewrite works.

| # | cddl-rs 0.10.7 behaviour | RFC 8610 | Rewrite |
| --- | --- | --- | --- |
| 1 | Bareword member keys that are also prelude names (`time`, `uri`, `number`, ...) are resolved as types, so `Event`'s `time:` never matches. | 3.5.1: a bareword before `:` is a text key. | All 448 bareword keys are quoted (`"time":`). |
| 2 | `~Map` unwrap inside a map fails (`QlogFile`, `QlogFileSeq` use `~LogFile`). | 3.7 | `~LogFile` is replaced by a group rule with LogFile's entries. |
| 3 | Negative JSON integers are accepted as `uint`. | prelude | `uint .size N` becomes `0..2^(8N)-1`. |
| 4 | `.regexp` matches unanchored, so `"zz"` passes as a `hexstring`. | 3.8.3: XSD regexps match the whole string. | Each regexp is wrapped as `^(?:...)$`. |
| 5 | Numbers are typed by their JSON spelling: `25` fails `float64` and `10.0` fails `uint`. | Appendix E (normative): JSON has one number type; `uint` means integral (`10`, `10.0`, `1e1` and `100e-1` all match), and float types only restrict the value range. | float16/32/64 also accept `int`, and integral numbers are rewritten exactly from their source text to integer form before validation. |
| 6 | `StatelessResetToken = hexstring .size 16` is applied to the text length, so a correct 32-hex-digit token fails. | | `.size 16` is enforced as exactly 16 hex-encoded bytes, the intent stated in the draft ("always 128 bits"). The WG's `cddl_validate.sh` strips this `.size`, and the editor's copy removed it after -13 (#621). |

There are also behaviours specific to the validator rather than the CDDL:

- **CLI quirks.** The CLI exits 0 even when validation fails, so the
  validator passes `--ci` and parses the output.
- **Error reporting.** cddl-rs reports a failing array element only as
  "matched the first N element(s)", and reports a failing type choice as one
  error per alternative (24 for `$QuicFrame`). For union members
  discriminated by a literal (`frame_type`, `capsule_type`, derived from the
  CDDL), the validator re-validates each element or value against the member
  its discriminator selects. Every element from the first failure on is
  checked. Any remaining flood of choice errors at one path is collapsed into
  a single "no type choice matched" message.

## Performance

Throughput depends on the size of the CDDL: cddl-rs looks rules up linearly.
For each batch, the validator therefore prunes the CDDL to the rules reachable
from that batch's root, groups items by rule, and runs batches in parallel.
On an 8-core machine:

| Input | Wall time | Single job (`--jobs 1`) |
| --- | --- | --- |
| 50,000 valid events (16 MB) | about 5.3 s | about 28 s |
| 50,000 failing quic-go events | about 4.5 s, including the detail pass | |
| quic-go fixtures (650–2,700 events) | 0.3–0.4 s | |

Before pruning, a 50k-event run took about 33 s wall.

`sample-valid.sqlog` is a hand-written, strictly conforming JSON-SEQ file. It
contains these events:

- `quic:connection_started`
- `quic:packet_sent` with crypto and padding frames
- `quic:packet_received` with ack, stream, max_data and new_connection_id frames
- `quic:recovery_metrics_updated`
- two `http3:frame_created` events, one with a headers frame and one with a
  settings frame

## Known limitations

- **Conditional comments.** Constraints that the drafts state only in comments
  are not checked, for example `; only if packet_type === "1RTT"`.
- **Not checked by design.** The validator does not check:
  - duplicate JSON member names (RFC 8259 says SHOULD be unique; the last one wins);
  - the "field names MUST be lowercase" rule, except where CDDL keys enforce it;
  - event time ordering.
- **Draft fixes after -13.** Changes in the editor's copy made after the
  published drafts are not applied. For example, `quic:ecn_state_updated`
  gained a `trigger` member after -13, so that member is rejected here.
