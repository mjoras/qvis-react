# qvis-react architecture and implementation contract

This is the binding contract for everyone implementing qvis-react. The parity specs in `docs/dev/parity/*.md`
describe **what** to build (1:1 with qvis). The qlog digests in `docs/dev/qlog-spec/*.md` describe the **input
format**. This document fixes **how** the code is organised, so independently written parts fit together.

## 0. Product decisions (final)

| Topic | Decision |
|---|---|
| qlog input | **Only** draft-ietf-quic-qlog-main-schema-14 + quic-events-13 + h3-events-13 (`.qlog` contained JSON, `.sqlog` JSON-SEQ). No aliasing of pre-final names (`transport:*`, `recovery:*`, `http:*`), no legacy (`qlog_version`) loading. Non-conforming files get a clear, non-modal diagnostic (see parser). Lenient only on *serialization* robustness (truncation repair, missing RS, BOM, uint64-as-string), never on schema names. |
| Editor's-copy clarifications | Accept the union of -14/-13 and the editor's copy where they don't conflict (e.g. `keys_unavailable` and `key_unavailable`). |
| Non-qlog inputs | Chrome `.netlog` and tshark JSON (TCP/TLS/HTTP2) are **ported** as client-side converters that emit latest-draft-shaped qlog. QUIC/H3 output uses the standard `quic:`/`http3:` names; TCP-stack output uses private namespaces `tcp:`, `tls:`, `http2:` (allowed by main-schema §8). |
| pcap / pcapng + keys | Not supported client-side (needs tshark). Show a clear message. Optional env hook `VITE_PCAP_BACKEND_URL` (qvis-server-compatible `/loadfiles?file=&secrets=` API) — only useful if that backend emits latest-draft qlog. |
| Remote files (`?file=`, `?list=`, Option 1) | Browser `fetch` first (CORS). On network/CORS failure, retry through our own Vercel Function `/api/loadfiles?file=<url>` (CORS proxy with SSRF guard, size cap; browsers may use it only from the app's own origin, see README "Deploying"). `vercel.json` rewrites `/loadfiles` → `/api/loadfiles` for qvis-server API shape compatibility. Client-side limits (security FIX, file-loading F10): a list loads at most 100 captures, 6 at a time; decompression stops at 512 MiB. |
| Routing | Small custom hash router (`src/app/router.ts`), not react-router: exact qvis URL semantics (`#/sequence?file=...`, pre-hash `?file=` migration, sticky query params). Remove the `react-router` dependency. |
| UI kit | Bootstrap 5.3 CSS + react-bootstrap 2 where convenient, with Bootstrap-4 parity overrides in `src/styles/global.css` (see `parity/app-shell.md` §8.7). Font: `'Avenir', Helvetica, Arial, sans-serif`, color `#2c3e50`. |
| Charts | D3 v7, imperative renderer classes ported from qvis (`*D3Renderer.ts`), mounted into refs from React components. Port line-by-line where possible; adapt only for (1) D3 v5→v7 API changes, (2) the new data model, (3) latest-draft event/field names. |
| State | zustand stores; qlog data lives in mutable class instances that are **never** deep-copied/frozen (see §3). |
| Demo data | Generated by our patched quic-go harness (`tools/qloggen`), CDDL-validated, in `public/examples/`. |
| Hosting | Vercel, static `dist/` + `api/` functions. `base: "./"` so subpath hosting also works (like qvis). |

## 1. Stack

Vite 8, React 19, TypeScript 6 (strict), D3 7, zustand 5, Bootstrap 5.3 + react-bootstrap 2, Vitest 5 (jsdom),
Playwright 1.64. Node ≥ 20. Path alias `@/` → `src/`.

Quality gates for every change: `npm run typecheck` (app, node/e2e and `api/` projects), `npm run lint` (0 errors),
`npm test`, `npm run build`, and `npm run e2e` (Playwright smoke suite, §5).

## 3. Core contracts (normative)

### 3.1 Data model — `src/model/`

**Normative:** `docs/dev/parity/data-model.md` §3.16 (pipeline, time model, normalization, group split, ordering,
lookup index, `ext` annotations, clones, change notification, TypeScript API in §3.16.12, old→new API table in
§3.16.13) and its decisions D1–D5, D7, D8 — **with these overrides** (user direction: strict latest drafts only):

1. **No alias table** (data-model D6 is reversed; drop `aliases.ts`, §3.16.4 steps 2-lenient/3/5 fix-ups). Event
   names are used exactly as logged: `fullName === loggedName`. Data is never fixed up (`data === raw.data`).
2. Instead, detect **non-conforming event names**: any event whose namespace is one of the pre-final categories
   (`transport`, `recovery`, `security`, `connectivity`, `http`, `qpack` when not listed in event_schemas …) or whose
   `quic:`/`http3:` type is not defined by quic-events-13 / h3-events-13 → warning diagnostic
   `event.nonconforming-name` (count + up to 5 sample names). The store turns it into toast **DM3**:
   title `Unsupported qlog event names in <filename>`, text
   `This file contains <n> events whose names are not defined by the latest qlog drafts (e.g. <samples>). qvis only supports draft-ietf-quic-qlog-quic-events-13 and draft-ietf-quic-qlog-h3-events-13 event names; the visualizations do not interpret these events.`
   Files with both `file_schema` and legacy `qlog_version` members (current quic-go output) are parsed normally
   (`file_schema` wins); their non-conforming names trigger DM3.
3. Legacy files (`qlog_version` without `file_schema`) are rejected by the parser with `LegacyQlogError`; the loader
   shows toast **X1** (file-loading spec).
4. Event name constants live in `src/model/names.ts` and are **generated from the drafts** (all quic-events-13 and
   h3-events-13 event types, plus loglevel/simulation). `src/qlog/schema/*` holds the data types.
5. Views always use the names.ts constants and the latest-draft field locations; none reads a pre-final field
   (top-level frame `length`, metrics `cwnd`, `onertt`, …). Events with non-conforming names keep their index (event
   numbers, deep links) and are shown as plain events where a view lists everything (sequence diagram chips, the Stats
   Events histogram), but never interpreted (no arrows, frames, packet sizes, flow control).
6. `protocolHint` / `transportNamespace` (data-model §9.10): `common_fields.protocol_type` first; otherwise `tcp:`
   events make a trace TCP only when it has no `quic:` events.
7. Private `event_schemas` URIs declare a namespace by a whole path segment (`https://…/112026/tcp`,
   `…/quic#chromium`; a file extension is ignored), never by substring.

## 4. React ↔ D3 conventions

- Each visualization keeps qvis's split: `XContainer.tsx` (page: configurator + renderer), `XConfigurator.tsx`
  (controls, auto-selection), `XRenderer.tsx` (React wrapper owning a `<div ref>` / `<svg ref>`), and
  `renderer/XD3Renderer.ts` (imperative class, framework-free, ported from qvis).
- D3 renderer classes take a container element (not an id) in the constructor, expose `render(...)`, and a
  `dispose()` that removes listeners (window scroll, document keyup, resize) and timers. The React wrapper creates
  the renderer in `useEffect` on mount, calls `render` when inputs change, and `dispose()` on unmount.
- D3 v5 → v7: `d3.event` → the `event` handler argument; `d3.mouse(node)` → `d3.pointer(event, node)`;
  `d3.zoom().on("zoom", () => d3.event.transform)` → `(event) => event.transform`; `d3.nest` → `d3.group`/`d3.rollup`;
  `selection.on(type, (d, i) => ...)` → `(event, d) => ...` (index no longer passed — use `nodes.indexOf` if needed);
  `d3.scaleOrdinal`/`d3.schemeCategory10` unchanged.
- Never put events or renderer instances in React state. Use refs. Re-render triggers come from config objects and the
  store's `revision`.
- Styles: keep qvis's ids/classes for DOM parity (e.g. `#MainMenu`, `#FileManagerContainer`) and port scoped CSS to a
  colocated `.css` file using those ids.
- Bootstrap 5 grid pitfalls (found during integration): `.row > *` gives **every** direct child of a row `width: 100%`,
  gutter padding and `flex-shrink: 0`; Bootstrap 4 only styled `.col*`. qvis puts `<p>`, checkboxes and buttons
  directly in `b-row align-h="center"`, so neutralize the rule with a selector scoped to your configurator
  (multiplexing-graph.md §8.5). There is deliberately no global override, because it would outrank `.container` and
  similar classes. Also never put padding on a `.container-fluid` that holds rows: its 15px gutter padding offsets the
  rows' −15px margins, and without it the page scrolls horizontally. Copy qvis's structure instead: panel colour and
  `padding: 0px 10px` on an outer `div`.

- Scoped CSS must not leak into the shared `ConnectionConfigurator`: Vue scoped rules never reached a child
  component's inner elements, so write `.my-configurator > .container-fluid > .row`, not `.my-configurator .row`
  (a descendant `.row { padding-bottom: 10px }` made the congestion panel 20px taller than qvis).
- Bootstrap 4.3.1 parity that is now global (`src/styles/global.css`): body font stack, `ul/ol` 40px indent, modal
  frame (`rgba(0,0,0,.2)` border, `.3rem` header corners); `#MainMenu .nav-link` has no colour transition. Views add
  only their own scoped rules on top.
- react-bootstrap: `<Modal id>` lands on `.modal-dialog`; set qvis's id on the `.modal` root in `onEnter`
  (`EventDetailModal`, `PacketizationInfoModal`). For qvis's `v-b-tooltip.hover` use `useHoverTooltip`
  (`components/shared/HoverTooltip.tsx`, CSS `.qvis-tooltip` in global.css): BootstrapVue's 50 ms delay, Popper 1 flip
  and Bootstrap 4 geometry, font and z-index, measured identical to hosted qvis. `OverlayTrigger` with a hover-only
  trigger logs a console error in dev, and its defaults differ from qvis (0.6 px lower, no delay).
- Buttons: the Bootstrap 4.3.1 focus look (ring on any `:focus`, also after a mouse click; normal colours on keyboard
  focus) is global (`.btn:focus` in global.css); views add no local copies.
- Content-Security-Policy (`vercel.json`, production only): `script-src 'self'`, `object-src 'none'`. Never add inline
  `<script>` to `index.html`, inline event handlers (`.attr("onclick", ...)`, `on*` attributes in HTML strings) or
  `eval`/`new Function`: production blocks them while the dev server (no CSP) runs them. Only `.text()` / React text
  for data; the single `.html()` sink (packetization tooltip) escapes every value.
- D3 v7 / browser gotchas: a linear axis over a degenerate domain (`[0,0]`) prints `0.000000` where d3 v5 printed `0`
  (use `format(",.0f")` or the multiplexing `withV5TickFormat`); Chrome logs negative or NaN SVG `width`/`height` as
  console errors (clamp to 0); on canvas, `fillRect` is not pixel-identical to qvis's `beginPath(); rect(); fill()`.
- Console policy: data and URL diagnostics that qvis logged with `console.error` are logged with `console.warn` (same
  text); `console.error` is reserved for exceptions, so the e2e suites can fail on any console error.

## 5. Testing contract

- Unit tests next to the code (`*.test.ts(x)`), Vitest + jsdom. Parsers and pre-processors must be tested against
  `tests/fixtures/latest/*` (real generated data) and small hand-written cases.
- Every visualization gets at least a smoke test that runs its data pre-processing on a fixture without throwing,
  plus assertions on key computed values (e.g. number of packets, byte totals, stream ids).
- Playwright e2e in `tests/e2e/` (`npm run e2e`; `playwright.config.ts` starts `vite` on port 5179, or reuses a running
  one outside CI): load demo files, visit every route, no console errors, screenshot. `smoke.spec.ts` fails a test on any
  console error or uncaught exception. The Vite dev server also serves repo files (`/scripts/cddl/sample-valid.sqlog`,
  `/tests/fixtures/**`), which the `?file=` tests fetch, so no test data goes into `public/`. Toasts are fixed bottom-center
  over the page (qvis parity) and swallow clicks: dismiss them (click) before clicking content underneath.
- `tests/e2e/all-views.spec.ts` loads Option 3 (and Option 4, the massive demo), selects traces through every
  configurator, asserts rendered content (SVG element counts, inked canvas pixels, Stats counts against
  `index.json`) and saves one screenshot per view to `$QVIS_SCREENSHOT_DIR` (default: the test output folder).
- Toast dismissal in tests: click toasts until none are left, waiting with `expect.poll(count).toBeLessThan(n)`
  (several toasts can expire at once); a forced click on a covered button lands on the toast instead. Click with a
  short timeout and ignore failures (`click({ force: true, timeout: 2000 }).catch(() => {})`): a toast can expire
  between `count()` and `click()`, and a plain click then waits for the whole test timeout.
- The e2e suite is hermetic: `playwright.config.ts` starts Chromium with `--host-resolver-rules` so every host except
  localhost fails to resolve. Fake remote URLs go through `page.route()`; comparisons with hosted qvis use committed
  golden data (`multiplexinggraph/__fixtures__/`) or scratch scripts outside the suite, never the network. Check for
  flakiness with `npx playwright test --repeat-each 2`.
- Concurrent Playwright runs share `test-results/`; pass `--output=<private dir>` when several run at once.
- Parity harness: same connection in `tests/fixtures/legacy/*.draft02.qlog` rendered by hosted qvis
  (https://qvis.quictools.info, Option 2 upload) vs `public/examples/*` rendered by qvis-react, same selections,
  screenshots compared side by side (`scripts/latest-to-legacy.mjs` makes the draft-02 files). Per-view harnesses:
  `src/components/multiplexinggraph/__fixtures__/` (golden DOM dump, e2e-tested).
