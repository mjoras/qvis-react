# Completeness critic: gaps and errors in the parity specs

Scope of this review:

- every document in `docs/dev/parity/` and `docs/dev/qlog-spec/`, plus `docs/dev/ARCHITECTURE.md` (binding contract);
- the whole qvis tree (`visualizations/src`, `visualizations/public`, repo root: `README.md`, `Dockerfile`,
  `.github/ISSUE_TEMPLATE/*`, `LICENSE`, `package.json`, `vue.config.js`, `.prettierrc`, `.gitignore`), walked file
  by file and function by function;
- qvis-server (`src/**`, `system/**`) and the pcap2qlog parts the specs cite;
- the three drafts in the published draft texts (ietf.org) and the editor's copies in `scratchpad/ref/qlog-wg/*.md`.

## 0. Method and overall result

Mechanical coverage checks (scripts in the scratchpad `critic/` folder, run on the reference tree only):

| Check | Result |
|---|---|
| Every source file referenced by at least one spec | 72/76 by name. The 3 `types/*.d.ts` shims carry no behaviour; `HelloWorld.vue` is described (not named) in app-shell §2.7 |
| Every string literal of 4 or more characters in `src/**/*.ts|vue` (comments stripped) found verbatim in a spec | all user-visible strings found. The only misses are `console.*` texts, Vue template expressions and import paths. The console texts are catalogued by prefix in each spec's §6 |
| Every method/function name in the source found in a spec | all, except names whose behaviour the specs describe by line citation instead (`hideLegend`/`showLegend`, `onPan`, `onZoom`, `packetMouseOver`, ...); behaviour verified present |
| Every hex colour and named CSS colour in the source | all present. The two misses (`#003f83` in `App.vue`, `#dcdcdc` in `FileManagerContainer.vue`) are inside CSS comments |
| Every numeric constant (2 or more digits, or decimal) in the 11 renderer and pre-processor files against its own spec | all present (the only misses are the SVG/XHTML namespace URIs) |
| Every `.on(...)`, `addEventListener`, `@click`, `@change`, `v-model`, `v-b-tooltip`, `b-modal` | all present, with correct semantics |
| Every query parameter read (`$route.query`, `location.*`, `indexOf` URL sniffing, qvis-server `req.query`) | all present in app-shell §5.1 / file-loading §3.12 |
| Resize, timers, `window.*`, `document.*` side effects | all present |

The per-view UI, rendering and algorithm content is exhaustive. **No user-visible qvis feature, control, string,
colour, query parameter, notification or hosting behaviour is missing.** The gaps found are cross-spec
contradictions, mostly stale assumptions that predate ARCHITECTURE §0/§3.1 (no aliasing, demo data from a generator),
plus a few unspecified consequences of the strict-names policy.
